# Verdict v0.12.0 — local verification

The observation behind the `v0.12.0` row of the compatibility matrix in
[`docs/laravel-ai-compatibility.md`](../../docs/laravel-ai-compatibility.md).

## What was run

The released tag was checked out detached at its own commit — `2e0e3f5d6f025c99e88ecb43e00c41e6489fbec5`,
which is `git rev-list -n 1 v0.12.0` — dependencies were installed from that tag's `composer.json`,
and the package's own test suite was run against the resolution that produced.

```sh
git worktree add --detach /tmp/v0120-verify v0.12.0
cd /tmp/v0120-verify
composer install
vendor/bin/pest
```

## Result

```
Tests:    11 skipped, 985 passed (3596 assertions)
```

Exit status 0. Date of run: 2026-08-27.

The eleven skips are the cases that require a real MySQL, MariaDB, or PostgreSQL connection; SQLite
has no `REPEATABLE READ`/`SERIALIZABLE` semantics and never raises SQLSTATE 40001, so they are
skipped rather than run against it.

## What this attests, and what it does not

It attests that the released `v0.12.0` source passed its own suite against that one resolution, on
one machine, on that date.

It does **not** attest a swept matrix. The verification kind recorded in the matrix is `local` for
exactly this reason: a CI sweep exercises several PHP, Laravel, and stability combinations across two
operating systems, and one local run exercises the single resolution recorded above. It also says
nothing about `verdict-console`, whose facts the matrix marks as reported by that repository.

Replacing this row with a `ci` row, citing a workflow run against a released tag, is a strict
improvement whenever such a run exists.
